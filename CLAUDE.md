# Working on sendg1

The question: do tactile sensors on the G1's feet measurably improve
locomotion policies? Every result is a paired comparison, blind vs tactile, so
anything that makes the two conditions differ in more than the actor's input
breaks the study. Background is in `docs/`; start with
[docs/design.md](docs/design.md).

## Running things

- Python env: uv, locked in `uv.lock` (Python 3.11, torch cu128). Install with
  `uv sync --frozen --extra dev`; run with `uv run ...`. Never re-lock or
  upgrade a package as a side effect; version changes are deliberate and
  committed with `uv.lock`.
- Tests: `uv run ./scripts/test.sh [pytest args]`. It unsets `PYTHONPATH`: this
  machine has ROS 2 Jazzy on it, which leaks Python 3.12 packages and crashing
  pytest plugins into the env (see [docs/install.md](docs/install.md)).
- Rendering is headless: `MUJOCO_GL=egl`.
- Training: mjlab's `train <task-id>`, or `scripts/sweep.py` for
  (task x observation-set x seed) grids. Output goes to `runs/` (gitignored);
  evaluation JSON goes to `results/` and is committed.
- mjlab is pinned to 1.6.0 (and rsl-rl to 5.4.2) in `pyproject.toml` too, so
  even an unlocked install cannot move them (`src/sendg1/_pin.py`).

## Rules that tests enforce

1. **The actor sees only what the real robot measures.** Every observation
   term declares its availability in `src/sendg1/common/obs/terms.py`; the
   allowlist test and an import-time check in `tasks/_register.py` reject
   anything else, including undeclared terms.
2. **Only the actor changes between observation sets.** Critic, rewards,
   events, terminations, terrain and network are identical
   (`tests/test_config_fingerprint.py`).
3. **Configs are fingerprinted.** When a fingerprint test fails after an
   intended change, inspect with `scripts/show_fingerprints.py --task <id>
   --dump`, re-record with `--write` in the same commit, and say which
   baselines need re-running.

## Conventions

- Code: 2-space indent, ruff line length 90, comments explain *why*.
- Adding a task: a directory under `src/sendg1/tasks/`, one
  `register_variants` call, one import in `tasks/__init__.py`. Adding an
  observation set: an `OBS_SETS` entry plus a branch in `build_groups`.
- Videos: every policy clip goes through `sendg1.video.EvalVideo`
  ([docs/videos.md](docs/videos.md)), so paired clips look the same.
- Visual style: the kyber palette, accent `#4cc9f0`, yellow `#fac055`, dark
  backgrounds; no purple or pink.
- One seed is directional only; five before any reported claim.
- Keep `README.md` short (intro, status, quick start, links). Details belong
  in `docs/`; update the page a change affects in the same commit. The banner
  is generated by `scripts/make_banner.py`.

## Layout

```
src/sendg1/
  common/          shared library: robot, obs terms/groups, rewards, events,
                   sensors, tactile sole, beam and box-push pieces
  tasks/           task packages; _register.py fans each across all obs sets
  eval/            the measurement protocol (versioned; it is the product)
  rl/              model classes beyond rsl_rl (the symmetric GRU)
  video/           EvalVideo: themed rendering + tactile HUD
  fingerprint.py   stable config hashing
tests/             allowlist, fingerprints, registration, import order, ...
scripts/           sweep, evaluate, aggregate, videos, fingerprints, tools
docs/              everything the README links to
runs/              training output (gitignored)
results/           eval JSON, one per (experiment, seed) — committed
```
